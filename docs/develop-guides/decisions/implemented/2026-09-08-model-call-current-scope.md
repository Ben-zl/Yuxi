# 模型调用与资源当前范围授权

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/model_call_service.py

## 问题

简单模型调用直接使用全局缓存会跳过当前用户授权；Provider/MCP 的历史创建者身份也可能越过移动或提升后的共享范围。

## 决策

简单调用服务通过数据库 repository 唯一解析供应商引用并检查当前用户可读权限、供应商启用状态和 chat 模型清单，成功后才使用规范资源 ID 选择模型。旧引用存在歧义时拒绝，不按用户部门选择同名资源。路由只传递认证上下文、请求和数据库会话。

Provider/MCP 权限策略要求 owner 命中当前读取范围；global 资源只允许超级管理员管理。同部门非 owner 管理员仍由 manage_scope 决定管理权。其他资源保留既有所有权策略。这是恢复既定共享契约的局部修复，没有待裁决的产品方案，因此直接记录 implemented。

## 替代方案

- 依赖全局缓存或前端模型列表授权：无法证明当前数据库权限。
- 修改所有资源的 owner 规则：会改变 Agent、Skill 与知识库的既有契约。

## 后果

每次简单调用增加数据库授权读取；权限检查完成后的并发配置变化仍属于请求间竞态，当前实现不锁定资源直至外部模型完成。

## 验证

聚焦权限、模型服务与路由测试覆盖跨部门旧 owner、global 提升、同部门 peer 管理范围和数据库停用模型。真实 TCP HTTP 与 PostgreSQL 隔离事务测试覆盖实际路由到 repository 的链路，并回读确认回滚清理；登录用户依赖及模型响应使用测试替身，不证明真实登录、外部模型或 Worker E2E。
