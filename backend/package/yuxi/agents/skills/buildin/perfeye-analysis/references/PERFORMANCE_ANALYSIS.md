本文档描述如何分析 perfeye 平台获取的性能数据，包括对 `LabelInfo.All` 中各项指标的详细解读。

## 数据获取

使用 `cli.py` 获取 perfeye 任务数据：

```bash
python3 <skill-dir>/scripts/perfeye_cli.py --uuid <task_uuid> --metrics
```

## LabelInfo.All 数据结构

`LabelInfo.All` 包含所有统计数据的汇总，是性能分析的主要数据源。

### BaseInfo（基础信息）

测试环境和版本信息，用于理解性能数据的上下文。

#### 关键字段

| 字段 | 说明 | 示例 |
|------|------|------|
| `CaseName` | 测试案例名称 | "场景测试(TDR)完整流程_High(10.11.144.215)" |
| `AppVersion` | 应用版本号 | "1.0.0.5949.181684" |
| `CPUType` | CPU 型号 | "Intel(R) Core(TM) i7-8700K CPU @ 3.70GHz" |
| `GPUType` | GPU 型号 | "NVIDIA GeForce RTX 2060" |
| `PictureQuality` | 画质设置 | "High" |
| `Resolution` | 分辨率 | "2560x1440" |
| `RAMSize` | 内存大小 | "15.9 GB" |
| `OSVersion` | 操作系统版本 | "Windows-10-10.0.19041-SP0" |
| `GraphicsAPI` | 图形 API | "DX11" |
| `Duration` | 测试时长 | "0d 0h 10m 26s" |
| `ReportTime` | 报告生成时间 | "2026-02-02 07:07:14" |

#### 分析要点

- **CPU 和 GPU 型号**：决定性能基线，影响性能预期
- **画质设置**：High/Medium/Low 等画质级别直接影响性能
- **分辨率**：2560x1440 (2K) vs 1920x1080 (1080p) 渲染负载差异约 78%
- **版本信息**：用于对比不同版本的性能变化
- **案例名**：说明测试场景，帮助理解性能数据背景

#### 常见画质级别

| 画质 | 说明 | 性能影响 |
|------|------|----------|
| **Low** | 低画质，特效最少 | 性能最好 |
| **Medium** | 中等画质，平衡性能和效果 | 性能中等 |
| **High** | 高画质，全特效 | 性能较差 |
| **Ultra** | 极致画质，最高质量 | 性能最差 |

#### 分辨率对性能的影响

| 分辨率 | 像素数量 | 相对 1080p | 性能影响 |
|--------|----------|------------|----------|
| 1920x1080 (1080p) | 207万 | 1.0x | 基准 |
| 2560x1440 (2K) | 368万 | 1.78x | 渲染负载增加 78% |
| 3840x2160 (4K) | 829万 | 4.0x | 渲染负载增加 300% |

### LabelFPS（FPS 统计）

分析游戏帧率表现，反映流畅度。

#### 关键指标

| 字段 | 说明 | PC 平台标准 |
|------|------|-------------|
| `AvgFPS` | 平均帧率 | ≥ 60 FPS（达标），≥ 90 FPS（优秀） |
| `TP90` | 90分位帧率 | ≥ 60 FPS（达标），≥ 90 FPS（优秀） |
| `Jank(/10min)` | 每10分钟卡顿次数 | < 10 次/10min（达标），< 5 次/10min（优秀） |
| `BigJank(/10min)` | 每10分钟严重卡顿次数 | < 5 次/10min（达标），< 2 次/10min（优秀） |
| `AllJank` | 总卡顿次数 | 越低越好 |
| `AllBigJank` | 总严重卡顿次数 | 越低越好 |

#### 分析要点

- **AvgFPS vs TP90**：如果 AvgFPS 高但 TP90 低，说明帧率不稳定
- **Jank vs BigJank**：BigJank 占比高说明存在严重性能瓶颈

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| AvgFPS < 60 | GPU 性能不足、渲染负载过重 |
| TP90 显著低于 AvgFPS | 帧率波动大、存在间歇性卡顿 |
| Jank > 20 次/10min | 资源加载阻塞、GC 频繁、主线程阻塞 |
| BigJank 占比 > 50% | 严重性能瓶颈（如复杂渲染、大量对象创建） |

### LabelModuleFPS（模块化 FPS 统计）

分析不同游戏状态下的帧率表现。

#### 关键指标

| 字段 | 说明 | PC 平台标准 |
|------|------|-------------|
| `Tp90(FPSState_1)` | 正常游玩状态的 90分位帧率 | ≥ 60 FPS（达标），≥ 90 FPS（优秀） |

#### 分析要点

- **FPSState_1**：正常游玩状态，排除加载界面、暂停菜单等非游戏场景
- **Tp90(FPSState_1) vs TP90**：正常游玩的 TP90 更能反映真实游戏体验
- 如果 Tp90(FPSState_1) 显著高于整体 TP90，说明非游戏场景（如加载界面）性能较差

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| Tp90(FPSState_1) < 60 | 正常游玩场景存在性能问题 |
| Tp90(FPSState_1) >> TP90 | 非游戏场景（加载、菜单）性能较差 |

### LabelCPU（CPU 统计）

分析 CPU 使用情况，识别 CPU 瓶颈。

#### 关键指标

| 字段 | 说明 | 判断标准 |
|------|------|----------|
| `AvgApp` | 平均应用 CPU 使用率（原始值） | 需结合平台判断 |
| `AvgApp(%)` | 平均应用 CPU 使用率（百分比） | < 80% 为健康 |
| `AvgCTemp` | 平均 CPU 温度（°C） | < 75°C 为正常 |
| `MaxApp(%)` | 最大应用 CPU 使用率（百分比） | < 95% 为健康 |
| `MaxCTemp` | 最大 CPU 温度（°C） | < 85°C 为正常 |

#### 分析要点

- **AvgApp(%) vs MaxApp(%)**：差距大说明存在 CPU 峰值，可能有突发计算任务
- **CPU 温度**：持续高温可能导致降频，影响性能
- **CPU 与 FPS 关系**：CPU 高占用但 FPS 低，说明存在 CPU 瓶颈

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| AvgApp(%) > 90% | CPU 瓶颈、逻辑计算过重 |
| MaxCTemp > 85°C | 散热不良、长期满载 |
| CPU 高但 GPU 低 | 逻辑复杂度高、物理计算/AI 过重 |

### LabelGPU（GPU 统计）

分析 GPU 使用情况，识别 GPU 瓶颈。

#### 关键指标

| 字段 | 说明 | 判断标准 |
|------|------|----------|
| `Avg(GPULoad)[%]` | 平均 GPU 使用率 | 60-90% 为健康 |
| `Avg(GPUFreq)[MHz]` | 平均 GPU 频率 | 需结合 GPU 型号判断 |
| `AvgGTemp` | 平均 GPU 温度（°C） | < 75°C 为正常 |
| `Max(GPULoad)[%]` | 最大 GPU 使用率 | < 95% 为健康 |
| `Max(GPUFreq)[MHz]` | 最大 GPU 频率 | 需结合 GPU 型号判断 |
| `MaxGTemp` | 最大 GPU 温度（°C） | < 85°C 为正常 |

#### 分析要点

- **Avg(GPULoad) vs Max(GPULoad)**：接近 100% 说明 GPU 饱和
- **GPU 频率**：频率未达到最大值说明可能有热降频
- **GPU 温度**：高温会导致降频，影响性能

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| Avg(GPULoad) > 95% | GPU 饱和、渲染负载过重 |
| Max(GPULoad) = 100% | GPU 瓶颈，需要优化渲染 |
| MaxGTemp > 85°C | 过热降频、散热不良 |
| GPU 高负载但 FPS 低 | 渲染效率低（DrawCall 过高、Shader 复杂） |

### LabelMemory（内存统计）

分析内存使用情况，识别内存问题和泄漏。

#### PC 平台指标

| 字段 | 说明 | 判断标准 |
|------|------|----------|
| `InitMemory(MB)` | 初始内存 | < 1000 MB 为优秀 |
| `AvgMemory(MB)` | 平均内存使用 | < 6000 MB 为正常 |
| `PeakMemory(MB)` | 峰值内存使用 | < 8000 MB 为健康 |

#### Xbox 平台指标

| 字段 | 说明 | 判断标准 |
|------|------|----------|
| `AvgTotalUsedMemory(MB)` | 平均总内存使用 | 需结合平台判断 |
| `MaxTotalUsedMemory(MB)` | 峰值总内存使用 | 需结合平台判断 |

**平台差异说明**：
- **PC 平台**：使用 InitMemory、AvgMemory、PeakMemory
- **Xbox 平台**：使用 AvgTotalUsedMemory、MaxTotalUsedMemory
- Xbox Series X 配置：16GB 统一内存（CPU+GPU 共享）

#### Xbox 内存判断标准

| 指标 | 优秀 | 良好 | 正常 | 偏高 | 严重 |
|------|------|------|------|------|------|
| **AvgTotalUsedMemory** | < 8 GB | 8-10 GB | 10-12 GB | 12-14 GB | > 14 GB |
| **MaxTotalUsedMemory** | < 10 GB | 10-12 GB | 12-14 GB | 14-15 GB | > 15 GB |

#### 分析要点

- **PC 平台**：InitMemory vs PeakMemory 差距过大说明有内存增长
- **Xbox 平台**：AvgTotalUsedMemory vs MaxTotalUsedMemory 差距反映内存波动
- **内存增长趋势**：需要多次运行对比，判断是否有内存泄漏
- **平台差异**：Xbox 使用统一内存架构，CPU 和 GPU 共享 16GB
- **AvgMemory vs PeakMemory**：Peak 远高于 Avg 说明存在峰值场景

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| PeakMemory > 11000 MB | 内存占用过高，可能有泄漏 |
| InitMemory > 7000 MB | 初始加载资源过多 |
| PeakMemory / InitMemory > 5 | 运行时内存增长过大 |

### LabelRenderer（渲染统计）

分析渲染相关指标，识别渲染瓶颈。

#### 关键指标

| 字段 | 说明 | 判断标准 |
|------|------|----------|
| `Avg(Drawcall)` | 平均 DrawCall 数量 | 根据画质区分（见下表） |
| `Max(Drawcall)` | 最大 DrawCall 数量 | 通常为 Avg 的 2-3 倍为健康 |
| `Avg(PrimitiveCount)` | 平均图元数量（三角形） | 根据画质区分（见下表） |
| `Peak(PrimitiveCount)` | 峰值图元数量 | 越低越好 |
| `Avg(VertexCount)` | 平均顶点数量 | 需结合场景复杂度判断 |
| `Peak(VertexCount)` | 峰值顶点数量 | 越低越好 |

#### DrawCall 和面数达标标准（按画质分级）

| 画质级别 | DrawCall 达标标准 | 面数（Primitive）达标标准 |
|----------|-------------------|--------------------------|
| **极高** | < 5000 | < 1000万（10000000） |
| **高** | < 4000 | < 700万（7000000） |
| **中** | < 2500 | < 400万（4000000） |
| **低** | < 1600 | < 200万（2000000） |
| **极低** | < 1000 | < 120万（1200000） |

**画质级别识别**：
- "Ultra"、"Very High"、"极高" → 极高
- "High"、"高" → 高
- "Medium"、"中" → 中
- "Low"、"低" → 低
- "Very Low"、"极低" → 极低

#### 分析要点

- **DrawCall 数量**：过高会导致 CPU-GPU 通信开销
- **图元数量（PrimitiveCount）**：影响 GPU 渲染负载，通常以百万为单位
- **顶点数量（VertexCount）**：影响顶点处理阶段负载
- **DrawCall 与 FPS 关系**：DrawCall 高且 FPS 低，需要合并渲染
- **Max vs Avg**：峰值远高于平均值说明存在复杂场景
- **画质影响**：画质越高，允许的 DrawCall 和面数标准越高

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| Avg(Drawcall) 超过当前画质标准 | DrawCall 过高，需要批处理 |
| Max(Drawcall) > 2 × Avg(Drawcall) | 存在极端复杂场景，需要优化 |
| Peak(PrimitiveCount) 超过当前画质标准 | 模型面数过多，需要减面或 LOD |
| Peak(VertexCount) > 5000万 | 顶点过多，需要简化模型 |
| DrawCall 高但 Primitive 低 | 合批不充分、材质过多 |

### LabelNetwork（网络统计）

分析网络使用情况，识别网络性能问题。

#### 关键指标

| 字段 | 说明 | 判断标准 |
|------|------|----------|
| `AvgRecv(KB/s)` | 平均接收速率 | 需结合游戏类型判断 |
| `AvgSend(KB/s)` | 平均发送速率 | 需结合游戏类型判断 |
| `MaxRecv(KB/s)` | 峰值接收速率 | 越低越好 |
| `MaxSend(KB/s)` | 峰值发送速率 | 越低越好 |

#### 分析要点

- **AvgRecv vs AvgSend**：接收速率通常远大于发送速率（客户端-服务器模式）
- **Max vs Avg**：峰值远高于平均值说明存在突发网络流量
- **单位**: KB/s（千字节/秒）

#### 问题诊断

| 症状 | 可能原因 |
|------|----------|
| AvgRecv > 500 KB/s | 接收数据过多，可能存在冗余数据 |
| MaxRecv >> AvgRecv | 存在突发流量（如加载资源、大量玩家同步） |
| AvgSend > 50 KB/s | 发送数据过多，可能需要优化同步策略 |
| MaxSend >> AvgSend | 存在突发发送（如批量上传） |

#### 优化建议

1. **减少接收数据量**
   - 使用增量更新而非全量同步
   - 压缩网络数据
   - 过滤不重要数据

2. **优化发送频率**
   - 使用批量发送
   - 降低非关键数据发送频率
   - 实现客户端预测

## 性能分析报告模板

### 0. 基础信息

**测试环境**：
- 案例名：CaseName
- 版本：AppVersion
- CPU：CPUType
- GPU：GPUType
- 内存：RAMSize
- 分辨率：Resolution
- 画质：PictureQuality
- 图形API：GraphicsAPI
- 测试时长：Duration
- 报告时间：ReportTime

### 1. 总体评估

- **FPS 评估**：AvgFPS / TP90 是否达标
- **流畅度评估**：Jank / BigJank 是否在可接受范围
- **资源评估**：CPU / GPU / 内存是否健康

### 2. 详细分析

#### FPS 分析
- 当前 AvgFPS：XX，TP90：XX
- 正常游玩 TP90 (FPSState_1)：XX
- 卡顿情况：Jank XX 次/10min，BigJank XX 次/10min
- 评估：达标 / 偏低 / 严重偏低

#### 渲染分析
- DrawCall：平均 XX，峰值 XX
- Triangle：平均 XX，峰值 XX
- 评估：健康 / 偏高 / 瓶颈


#### CPU 分析
- 平均使用率：XX%，峰值：XX%
- 温度：平均 XX°C，峰值 XX°C
- 评估：健康 / 瓶颈 / 过热

#### GPU 分析
- 平均使用率：XX%，峰值：XX%
- 温度：平均 XX°C，峰值 XX°C
- 评估：健康 / 饱和 / 过热

#### 内存分析
- 初始：XX MB，平均：XX MB，峰值：XX MB
- 增长：峰值 / 初始 = XX
- 评估：健康 / 偏高 / 可能泄漏

#### 网络分析
- 平均接收：AvgRecv XX KB/s，峰值 MaxRecv XX KB/s
- 平均发送：AvgSend XX KB/s，峰值 MaxSend XX KB/s
- 评估：正常 / 偏高 / 突发流量

### 3. 问题识别

根据各指标判断标准，识别存在问题的模块和指标。

### 4. 优化建议

针对识别出的问题，提供具体优化建议：
- FPS 优化：降低渲染负载、使用 LOD、多线程渲染
- JANK 优化：异步加载资源、优化 GC、平滑帧率
- 内存优化：对象池、资源复用、及时释放
- GPU 优化：减少 DrawCall、优化 Shader、降低分辨率
- 网络优化：减少数据同步频率、压缩网络数据、使用增量更新

## 性能基准

### PC 平台基准

| 指标 | 优秀 | 良好 | 达标 | 偏低 | 严重 |
|------|------|------|------|------|------|
| **AvgFPS** | ≥90 | ≥75 | ≥60 | 30-60 | <30 |
| **TP90** | ≥90 | ≥75 | ≥60 | <60 | <60 |
| **Jank(/10min)** | <5 | 5-10 | <10 | 10-20 | >20 |
| **BigJank(/10min)** | <2 | 2-5 | <5 | 5-10 | >10 |
| **AvgMemory(MB)** | <4000 | 4000-6000 | <8000 | 8000-10000 | >10000 |
| **Avg(GPULoad)[%]** | 60-80 | 80-90 | <90 | 90-95 | >95 |
| **GPUTemp** | <70 | 70-75 | <75 | 75-85 | >85 |

### PC 平台渲染基准（按画质分级）

DrawCall 和面数的基准标准根据画质设置有所不同：

| 画质级别 | DrawCall 优秀 | DrawCall 良好 | DrawCall 达标 | 面数优秀 | 面数良好 | 面数达标 |
|----------|--------------|--------------|--------------|----------|----------|----------|
| **极高** | < 3500 | 3500-4500 | < 5000 | < 700万 | 700-900万 | < 1000万 |
| **高** | < 2500 | 2500-3500 | < 4000 | < 500万 | 500-650万 | < 700万 |
| **中** | < 1500 | 1500-2200 | < 2500 | < 300万 | 300-380万 | < 400万 |
| **低** | < 1000 | 1000-1400 | < 1600 | < 150万 | 150-180万 | < 200万 |
| **极低** | < 600 | 600-900 | < 1000 | < 90万 | 90-110万 | < 120万 |

**说明**：
- 画质越高，允许的 DrawCall 和面数标准越高
- 在性能分析时，需要根据任务的 BaseInfo.PictureQuality 字段确定当前画质级别
- 然后使用对应画质级别的达标标准进行评估
